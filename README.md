# Homelab Sysadmin AI

A local-first Python assistant for diagnosing Linux and Docker homelab health. It collects structured telemetry, applies deterministic health rules, and can send a sanitized snapshot to a local Ollama model for explanation and remediation guidance.

## Highlights

- Disk, host, network, and Docker health checks
- Structured JSON snapshots suitable for automation or an LLM
- Local Ollama integration; no cloud model required
- Defensive prompt/data separation for untrusted telemetry
- Allowlisted diagnostic command runner; the model cannot execute arbitrary shell commands
- Audit logging and automated tests
- CLI output for quick homelab troubleshooting

## Architecture

```
Linux / Docker host
        |
        v
Python collectors -----> structured snapshot
        |                       |
        |                       v
        |                deterministic status
        |                       |
        +---------------------->|
                                v
                     local Ollama / Qwen
                                |
                                v
                  diagnosis + remediation
                                |
                                v
                  human-approved safe actions
```

## Quick start

Requires Python 3.10+ and, for AI analysis, Ollama running locally.

```bash
git clone https://github.com/jevonj05/homelab-sysadmin-ai.git
cd homelab-sysadmin-ai
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
python -m agent.main --path /mnt/storage
```

Run without AI:

```bash
python -m agent.main --path / --no-ai
```

Run tests:

```bash
pytest -q
```

## Security model

Telemetry is treated as untrusted data. The LLM receives system data inside explicit data boundaries and is instructed never to follow instructions found in telemetry. AI output is advisory only. Shell text generated by the model is never executed directly. Any executable diagnostic action must map to a predefined allowlisted action in `agent/command_runner.py`.

See `docs/security-model.md` for details.

## Project status

Functional portfolio implementation. Designed for a Linux/Docker homelab and intentionally conservative about system modification. Hardware/service availability varies by host, so individual collectors return structured errors instead of crashing the application.
